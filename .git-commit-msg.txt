feat(core): engine.run(...) 自动嗅探 PDF 字节并按 PDF 双通道处理

之前 engine.run(byte[]) 在检测到 %PDF- 魔数时抛错让用户改用 runPdf(byte[])，
现在直接自动转发 runPdf(...) 并平铺所有页结果。

- PPOcrV6Engine.run(byte[]) 命中 PDF → 转发 runPdf(...) → flatMap 平铺
- PPOcrV6Engine.run(Path) 读头部 1024 字节嗅探 → 默认 FS 命中 PDF 同样转发 runPdf
  - 非默认 FileSystem（ZIP / JIMFS / 内存 FS）按字节走 run(byte[]) 嗅探
- 新增 PPOcrV6Engine.run(InputStream) 重载
- run(byte[]) 与 BaseStructuredParser.parse(byte[]) 现在 throws IOException
  （PDF 解析需要传播；与 parse(InputStream) 一致）

影响：
- template.invoice().parse(pdfPath) 直接生效，无需先知道"哦发票是 PDF"
- 用户无感切换图片 / PDF；下游结构化解析器（idCard / driver / vehicle 等）继续按图片设计
- 调用方需要 catch IOException（破坏性 API 变更）

测试：
- 新增 PdfEngineRunPdfIntegrationTest#runBytesAutoDispatchesPdfAndFlattensPages
  验证多页 PDF 自动分发与平铺
- 全模块 0 失败测试

文档：CLAUDE.md 同步入口行为。
